# P2 结构计算性能记录

## 结论

P2 候选版不引入 Web Worker。确认规模上限附近的矩阵求解中位数为 `22.29 ms`，求解加结果适配中位数为 `25.50 ms`，五次最大值分别为 `27.55 ms` 与 `27.26 ms`。当前数据不支持为首版增加 Worker 通信、序列化和错误传播复杂度。

首轮检查发现一次性渲染 16,274 个结果表行会在 jsdom 中耗时约 8.81 s。该问题不是求解线程问题，因此没有用 Worker 掩盖；结果明细改为按需展开，曲线数值表对超大模型保留端点、极值、跳变与代表点。修改后初始结果壳只渲染 6 个控制值行，jsdom 记录为 `73.79 ms`。完整曲线仍使用全部计算点，每张曲线的可见数值表最多 240 行。

若工程签收人要求低于 `25 ms` 的交互门槛，或后续放宽 300 自由度上限，应重新执行本基准后再裁决；本记录不替代用户体验签收。

## 环境

- 日期：2026-07-19（Asia/Shanghai）
- 操作系统：Windows 11 10.0.26200，x64
- CPU：13th Gen Intel Core i7-13790F
- Node.js：v24.15.0
- Chrome：150.0.7871.125
- 分支：`phase/p2-structural-mechanics`
- 运行方式：Vitest/Node 主线程；与浏览器交付使用同一 TypeScript 求解与适配函数

## 模型与方法

- 模型：10×10 平面刚架网格
- 节点：100（冻结上限）
- 单元：180（冻结上限 200 以内）
- 自由自由度：297（冻结上限 300 以内）
- 约束：节点 N0 的 `u/v/θ=0`
- 荷载：节点 N99 的 `Fy=-1000 N`
- 材料/截面：`E=200 GPa`、`A=0.01 m²`、`I=8e-5 m⁴`
- 预热：1 次；记录：5 次；计时使用 `performance.now()`

运行命令：

```text
npx vitest run qa/performance/p2-structural-benchmark.test.ts --reporter=verbose
```

## 结果

| 路径 | 5 次耗时 / ms | 中位数 / ms | 最大值 / ms |
|---|---:|---:|---:|
| `solveFrameFiniteElement` | 27.551, 24.709, 18.759, 19.468, 22.290 | 22.290 | 27.551 |
| `runStructuralCalculation`（求解+展示适配） | 26.797, 24.260, 27.263, 25.496, 24.293 | 25.496 | 27.263 |

UI 补充记录：Vue Test Utils + jsdom，ECharts 组件以 stub 隔离，只测结果壳与表格 DOM；按需展开优化后初始渲染 6 行，`73.790 ms`。该数字用于定位 DOM 量级，不当作真实 Chrome 绘制耗时。

## 浏览器补充检查

离线单 HTML 在 Chrome 桌面与 Pixel 7 模拟视口执行 28 项 Playwright 测试，P2 默认梁、桁架、刚架、影响线和移动荷载均完成计算；页面无横向溢出，关键输入和按钮不小于 44 px。该组测试用于交互和交付回归，不冒充确认规模模型的精确浏览器微基准。

## 重跑规则

以下任一变化必须重跑并更新本文件：

- 节点、单元或自由度上限变化；
- 稠密矩阵求解器、结果采样数量或端力恢复算法变化；
- 引入 Worker/WASM；
- 支持多跨、释放、内部铰或三维结构；
- 目标浏览器或最低设备等级变化。
