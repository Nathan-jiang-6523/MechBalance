# 力学快速计算工具箱：从立项到 P1 的开发流程总结

> 总结范围：首次需求沟通至 2026-07-19。  
> 当前基线：`e03bba1 feat: support calculator expressions in P1 inputs`。  
> 当前阶段：P1 功能开发完成，等待力学负责人执行最终工程验收 `P1-H05`。

## 1. 项目起点

最初目标不是制作展示公式的网站，而是给机械结构工程师提供快速结论：

- 工程师无需安装 Python、Node.js 或其他运行时。
- 双击 HTML 或快捷方式，在最新版 Chrome 中打开 Web UI。
- 计算过程可以复杂，但用户侧只看到输入、结果、曲线、警告和必要公式。
- 逐步覆盖材料力学、结构力学、板壳力学、二维有限元和拓扑优化。

首轮架构判断：把“单 HTML”视为发布形态，不把它变成源码组织方式。源码保持模块化，构建时再打包为一个离线 HTML。这样既方便开发测试，也满足零安装交付。

## 2. 技术栈确认

最终采用：

| 层级 | 技术 | 选择原因 |
| --- | --- | --- |
| Web UI | Vue 3 + TypeScript | 表单和结果组件化；输入输出有类型约束 |
| 构建 | Vite + `vite-plugin-singlefile` | 将 JS、CSS、字体打包进单个 HTML |
| 样式 | CSS Variables + Scoped CSS | 轻量、可控，不依赖在线组件库 |
| 曲线 | Apache ECharts | 绘制梁的 `V/M/θ/v` 曲线 |
| 公式 | KaTeX | LaTeX 风格公式、MathML、离线字体内嵌 |
| 普通计算 | TypeScript 纯函数 | 便于单元测试、审查和复用 |
| 测试 | Vitest + Playwright | 计算回归、Chrome 桌面和移动端验收 |
| 后续重计算 | Web Worker + TypedArray | 为 P4 拓扑优化预留；防止 UI 阻塞 |

明确不采用：Laravel/Livewire、Electron、目标机 Python 服务、在线 CDN、云端 API、账号和数据库。

## 3. 产品路线图收敛

项目按四期推进：

- P1：材料力学 MVP。
- P2：机械接口、分段/超静定梁、桁架和刚架、影响线。
- P3：板壳闭式解和屈曲初算；强制显式选择边界条件。
- P4：Q4 平面应力有限元和 SIMP 拓扑优化；结果标记为“概念设计”。

P1 首款选择“截面性质 + 简支/悬臂梁综合计算器”，原因：一款工具即可同时验证单位、示意图、反力、内力、应力、挠度、极值、曲线、警告和离线交付。

## 4. P1 需求确认过程

### 4.1 范围确认

首批截面只包含：

- 矩形。
- 空心矩形。
- 实心圆。
- 圆管。

I/H、T 形后续开发；L 形、槽形、任意组合截面继续后置。

P1 十项功能：

1. 截面性质：`A`、形心、`I`、`W`、`J`。
2. 轴向拉压、伸长、温度变形。
3. 圆轴扭转、扭转角、功率—转矩—转速。
4. 简支梁：集中力、均布载荷、集中力矩。
5. 悬臂梁：端力、均布载荷、端矩。
6. 多载荷叠加以及剪力、弯矩、转角、挠度图。
7. 梁弯曲正应力和剪应力。
8. 弯扭组合、主应力、von Mises、Tresca。
9. 欧拉压杆稳定和长细比判断。
10. 平面应力莫尔圆。

另交付独立单位换算器，不计入上述十项。

### 4.2 工程规则确认

- 默认一致单位制：`t–mm–s–N–MPa`。
- `t` 只代表质量吨，不代表力；未来吨力必须写作 `tf`。
- 工程单位优先，SI 单位后置。
- 内核统一转 SI 计算，结果再转显示单位。
- 梁理论：Euler–Bernoulli、等截面、常 `E/I`、线弹性、小变形。
- 梁底层：四阶方程 `EI·v''''(x)=q(x)`，采用奇异函数/Macaulay 或等价分段多项式。
- 载荷：点力、点矩、分段均布载荷；原始输入最多 10 项，后台合并前计数。
- 支承：简支梁、左固定悬臂梁、右固定悬臂梁。
- 点力和点矩支持“方向 + 非负幅值”或“带符号数值”两种互斥模式。
- `L/h<10`：强警告但继续计算。
- `|v|max/L>1%`：强警告但继续计算。
- 不开发打印、PDF、Word、Excel或报告模板；结果只在 Web UI 展示。

### 4.3 公式和验收边界

- Codex 负责从公开网页、制造商资料、在线数据表和自身知识整理公式。
- 禁止读取用户本地参考书/PDF。
- 用户确定的坐标、正负号、预期结果和容差拥有最终验收优先级。
- 公式与用户验收真值冲突时停止对应实现，交由用户裁决。
- 用户提供 48 个验收算例；测试保持独立，不按程序结果反向修改真值。
- 材料预设保留 AL6061-T6、SPCC；删除各向异性的 PBT+30GF。

### 4.4 初始任务分工

- 验收算例组：列出待填写的验收算例表。
- 需求确认组：建立 P1 决策确认表。
- 工程初始化组：建立独立项目目录和本地 Git 仓库。
- 用户：冻结工程规则、填写真值、裁决分歧。

## 6. 实际开发阶段

### 阶段 A：规格和任务清单

先建立规格、确认表、验收算例表和 30–60 分钟粒度任务清单。先冻结范围，再写计算代码，避免 P1 向 P2/P3/P4 蔓延。

主要文件：

- `ai/memory-bank/site-setup.md`
- `ai/memory-bank/p1-confirmation-form.md`
- `ai/memory-bank/p1-acceptance-cases-form.md`
- `ai/memory-bank/tasks/mechanics-p1-tasklist.md`

### 阶段 B：公共底座

建立：

- 计算器输入/输出/警告契约。
- SI 内部单位和共享换算表。
- 数值格式化、负零处理和有限数检查。
- 统一字段校验。
- 材料预设和手工覆盖。
- 单位换算器。
- 截面性质纯函数内核和 SVG 示意图。

设计原则：`src/core/` 不生成 HTML；UI 只通过明确的数据契约调用内核。

### 阶段 C：四阶梁内核

按以下顺序开发：

1. 梁、支承和载荷数据结构。
2. 奇异函数及积分链。
3. 载荷叠加。
4. 简支/悬臂边界条件。
5. `V/M/θ/v` 任意位置场求值。
6. 点力剪力跳变和点矩弯矩跳变。
7. 力、力矩平衡残差。
8. 解析极值候选搜索。
9. 401 基础点 + 关键点的绘图采样。
10. 弯曲应力和实心矩形剪应力恢复。

计算链：

`输入 → 算式解析 → 字段校验 → 单位转 SI → 纯函数求解 → 平衡/适用性检查 → 结果单位转换 → UI/曲线/警告`

### 阶段 D：梁综合 Web UI

完成载荷编辑、支承和载荷示意、反力、极值、应力、两块可切换曲线、警告和公式区域。

交互规则：

- 首次计算需点击按钮。
- 首次成功后，合法输入修改约 300 ms 防抖自动重算。
- 非法输入使旧结果失效，禁止继续显示“计算成功”。
- 页面输入在上、结果在下；结果先结论、公式后置展开。

### 阶段 E：源程序和 QA 分离

按用户要求规范目录：

- `src/`：生产源码。
- `qa/unit/`：单元和验收回归。
- `qa/e2e/`：Chrome 交互/截图验收。
- `qa/fixtures/`：48 个验收真值。
- `qa-results/`：测试结果和截图，Git 忽略。
- `docs/formulas/`：公式 ID、版本、符号、假设和适用边界。

### 阶段 F：弯矩问题独立校核

发现梁弯矩可能异常后，没有直接按界面曲线调整公式，而是增加两道独立门禁：

- 10 个公开闭式梁弯矩算例。
- 固定版本 `IndeterminateBeam@4d504df` 逐点交叉验证。

定位并修复“无物理跳变的端点被绘图采样制造出假弯矩跳变”问题。验收规则：10 次不同公开结果全部一致才视为通过。

### 阶段 G：补齐 P1 其余功能

依次完成：

- 分段串联杆轴向拉压、机械伸长、自由温变、完全约束温度应力。
- 实心圆轴/圆管扭转、扭转角、功率—转矩—转速。
- 平面应力、莫尔圆、主应力。
- 弯扭组合、von Mises、Tresca、强度利用率。
- 四类端部约束欧拉压杆、弱轴控制和长细比判断。

每个模块执行同一流程：公式登记 → 纯函数内核 → 单元测试 → UI → E2E。

### 阶段 H：UI 和输入精修

开发后根据实际使用继续修正：

- 截面图尺寸 `h` 与 `x` 坐标轴遮挡：尺寸标注和坐标轴分层，并加入桌面/移动回归。
- 莫尔圆文字遮挡：标签避让；重合点合并显示。
- 扭转输入：补充 `G` 直接输入及 `E+ν` 换算模式。
- 公式可读性：引入 KaTeX；分式、上下标、希腊字母和 MathML 离线呈现。
- 输入效率：P1 数值框支持安全算式，如 `0.6*100`、`100*(1-5%)`；不使用 `eval`。

## 11. 后续统一开发流程

后续 P2–P4 沿用以下门禁：

1. 用户冻结边界条件、坐标、符号、单位和输出范围。
2. Codex 建立公式登记和适用边界。
3. 用户提供独立验收真值及容差。
4. 先写纯函数内核和单元测试。
5. 再接入 UI、示意图、曲线和警告。
6. 对关键结果引入第二套独立公开工具或闭式解交叉验证。
7. 执行桌面/移动 Chrome E2E 和断网单 HTML验收。
8. 用户完成工程签收后，才进入下一阶段。

此流程的核心：范围先冻结、真值独立、内核与 UI 分离、关键结论双重校核、构建结果不污染源码仓库。
